documentacion del proyecto /hotel2/

sistema de reservas y administracion de usuarios/habitaciones para un hotel
proyecto final programacion 2 - utu ctt (gerónimo ledesma)

1. descripción general del sistema

el sistema de gestión para hotelería hotel2 funcionaría como una aplicación web desarrollada en php y mysql diseñada para administrar de forma centralizada las reservas, el catálogo y disponibilidad de habitaciones, el registro de clientes y la gestión (simulada en este caso) de pagos.

ofrece dos modos principales de uso:

  • portal público: permite a los clientes explorar habitaciones, verificar el estado de ellas y realizar reservas en línea.
  • panel administrativo (/views/admin/): interfaz protegida por rol para la gestión CRUD (crear, editar, etc...) completa de usuarios, habitaciones y reservas.

2. módulos implementados

módulo descripción y funcionalidades
LOGIN Y USUARIOS 🔒 registro, inicio de sesión, cierre de sesión y control de acceso (a los distintos /views/ basado en roles (cliente y admin).
HABITACIONES 🏠 catálogo interactivo con filtro de estado (disponible, mantenimiento, inactiva), fotos, precios y capacidad.
RESERVAS 📅 sistema de reserva de habitaciones para clientes y panel de administración para modificar las reservas ya existentes.
PAGOS 💳 simulación de procesamiento de pagos con tarjeta de crédito asociadas a las reservas.

3. tablas utilizadas desde php

el sistema interactúa mediante PDO y Prepared Statements con 4 tablas relacionales en mysql:

  • usuarios -> almacena los datos personales, como cédula (ci), nombres, apellidos, email, contraseña, rol (cliente/admin), estado y fecha de nacimiento.
  • habitaciones -> almacena número de habitación, categoría (simple, doble, suite), precio por noche, capacidad, estado e imagen (puede ser /directorio/ o https://una.url.com).
  • reservas -> vincula un usuario (ci_usuario) con una habitación (numero_hab), incluyendo fechas de ingreso/salida y el estado del pago.
  • pagos -> registra las transacciones confirmadas (id_reserva, número de tarjeta procesada y monto pagado).

5. clases principales y patrones de diseño

CLASES PRINCIPALES (/models/):

  • Conexion (config/Conexion.php): administra el objeto PDO (conexion y gestion php-db) para la base de datos.
  • UsuarioFactory (models/UsuarioFactory.php): fábrica para la construcción de usuarios según su rol.
  • Usuario, Habitacion, Reserva: clases modelo encargadas del acceso a los datos.

PATRONES DE DISEÑO:

1. Singleton 🔄 (config/Conexion.php)

  • problema que resuelve: evita la apertura repetitiva e innecesaria de múltiples conexiones a la base de datos mysql, optimizando el uso de recursos de nuestro servidor.
  • implementación: posee un constructor privado y un método estático obtenerInstancia() que retorna una única instancia reutilizable de la clase PDO durante el ciclo de vida de cada solicitud HTTP.

2. Factory 🏭 (models/UsuarioFactory.php)

  • problema que resuelve: centraliza la creación de estructuras de usuario (para los administradores) evitando duplicar lógica al registrar o editar clientes y demás administradores.
  • implementación: el método crearUsuario($tipo, $datos) procesa los parámetros recibidos y configura los atributos, permisos y valores por defecto específicos según el rol (admin o cliente) antes de interactuar con la base de datos.

6. instrucciones de ejecución

1️⃣ preparación de la base de datos

  1. ejecutar phpMyAdmin o cliente mysql habitual.
  2. ejecutar en orden los scripts SQL incluidos en el proyecto:
    • estructura.sql (crea la base hotel_db y sus 4 tablas).
    • datos.sql (inserta los datos iniciales de prueba).

2️⃣ despliegue local

  1. copiar la carpeta del proyecto dentro del directorio raíz de su servidor local (ejemplo: xampp/htdocs/hotel2).
  2. verificar la configuración de tu base de datos en config/Conexion.php (configurado por defecto para localhost, con el usuario root y sin contraseña).
  3. asegurarse de cambiar $base_url = '/hotel2/'; por tu URL BASE en includes/init.php.
